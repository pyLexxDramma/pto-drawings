# Геометрия DWG/DXF: CSV для отрисовки и подсветки

Документ для бэкенда и конвейера. Фронтенд рисует чертёж из CSV (линии, полилинии,
подписи) и использует те же данные для режима «Подсветка». Контракт markdown
листа — в [`page-contract.md`](page-contract.md).

## API

| Кто | Маршрут | Ответ |
| --- | --- | --- |
| Конвейер | `GET /jobs/{jobId}/pages/{n}/geometry` | `text/csv` |
| PTO (прокси) | `GET /api/documents/{documentId}/pages/{n}/geometry` | `text/csv` |
| Запасной путь | `GET /jobs/{jobId}/pages/{n}/preview?format=png` | PNG |

Только для DWG/DXF. Для PDF — `404` (лист рисует pdf.js).

Первый разбор листа на бэкенде: 3–8 с (до ~35 с на очень больших файлах).
Повторные запросы — из кэша.

## Формат CSV

```
# bbox=167.7,-179.4,797.3,265.8; units=mm; scale=1:40; primitives=914; y=up
type,layer,color,lw,geom,text,size,rot,anchor,valign,width,id
line,ARMATURA,#ff7f9f,0.15,309.7 -60.4 308.5 -60.4,,,,,,
polyline,линия 05,#000000,0.5,328.8 219.5 268.8 219.5 268.8 144.5 328.8 144.5,,,,,,
text,,#000000,,301.3 236.3,Фундамент сборный Ф-1,5.0,,center,middle,80.2,7F3A
```

Первая строка — метаданные (`# bbox=…; units=…; scale=…`). Далее заголовок
колонок, одна строка на примитив. Парсер ищет колонки **по имени** в заголовке.

| Колонка | `type=line/polyline` | `type=text` |
| --- | --- | --- |
| `type` | `line` \| `polyline` \| `text` | обязательно |
| `layer` | слой чертежа | слой |
| `color` | `#rrggbb` | `#rrggbb` |
| `lw` | толщина, мм | — |
| `geom` | `x1 y1 x2 y2 …` | точка вставки `x y` |
| `text` | — | содержимое подписи |
| `size` | — | высота текста, мм |
| `rot` | — | поворот, градусы |
| `anchor` | — | `left` \| `center` \| `right` |
| `valign` | — | `top` \| `middle` \| `bottom` \| `baseline` |
| `width` | — | ширина блока, мм (справочно) |
| `id` | — | **object ID** для подсветки — см. ниже |

### Колонка `id` (подсветка)

Опциональна. Стабильный идентификатор объекта DWG (handle / entity id).

Должен совпадать с комментарием в markdown листа:

```markdown
<!-- obj:7F3A -->
Фундамент сборный Ф-1
```

Без `id` фронтенд пытается связать подпись с абзацем по тексту (менее точно).

## Координаты

1. **Ось Y вверх** — как в чертеже. Ориентир — `bbox` из первой строки, не нули.
2. **Единицы — мм листа**, не мировые координаты площадки.
3. **RFC 4180** для полей с запятыми и кавычками.
4. **Переносы в подписях** — литерал `\n` (два символа: `\` и `n`). Фронтенд
   разбивает на строки при отрисовке и при расчёте зоны подсветки.
5. Колонка `width` справочная; переносы уже расставлены на стороне конвейера.

## Ошибки и краевые случаи

| Ситуация | Ответ API |
| --- | --- |
| Лист только из внешних ссылок | `404` + текст |
| Служебный / виртуальный лист | `404` + текст |
| PDF | `404` |

Фронтенд при `404` показывает плашку; при необходимости — PNG из `preview`.
